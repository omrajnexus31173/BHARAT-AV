# BHARAT-AV Camera Integration

This update adds a separate **REAL CAMERA** workspace and preserves the existing 2D/3D simulation modes and their original simulation engine.

## What's included

- Laptop webcam and external USB/UVC camera selection through the browser's MediaDevices API.
- Mobile camera pairing from a QR link using PeerJS signalling and a WebRTC media stream.
- Browser-side live object detection using TensorFlow.js COCO-SSD Lite MobileNet.
- Bounding boxes, class labels, confidence scores, and a simple live inference FPS indicator.
- Separate Simulation and Real Camera workflows; existing scenarios, simulation controls, and reports are retained.

## Run it

```bash
npm install
npm run dev
```

Open the Vite URL in Chrome or Edge. Laptop webcam and USB/UVC cameras require a secure browser context (HTTPS or localhost). Grant camera permission when prompted.

## Mobile QR pairing

1. Host this app on an HTTPS URL accessible to both the laptop and phone.
2. Open the HTTPS app on the laptop and select **Real Camera → Mobile QR → Generate pairing QR**.
3. Scan the QR code with the phone, open the link, and press **Start camera**.
4. Allow camera permission. Keep the phone page open; the laptop should receive its live WebRTC stream.
5. Load the detection model on the laptop and press **Start detection**.

PeerJS uses its public signalling service by default. Both devices need internet access. Some restrictive networks/NATs may require a TURN relay; no TURN server credentials are bundled. The QR image is generated by an external QR image service and contains a temporary peer/session URL.

## USB and USB-C notes

- Standard USB-A/USB-C UVC webcams should appear in the camera selector after connection and permission is granted.
- A USB-C connector alone does not make a phone a webcam. The phone OS/device must expose a webcam/UVC mode, or a compatible webcam bridge/driver must be installed. Some Android devices support a native USB webcam mode; support varies by model and OS.
- A phone connected by cable but not exposed to the operating system as a webcam will not appear in `enumerateDevices()`.

## Detection scope and limitations

COCO-SSD supports common COCO classes, mapped here to Vehicles (car, truck, bus), Pedestrians (person), Cattle/Animals (cow and selected animals), and Motorcycles/Bicycles (motorcycle, bicycle). It does **not** include potholes. Pothole detection requires a pothole-specific trained model and dataset; the UI explicitly reports this instead of fabricating detections.

The camera detections currently render in the Real Camera workspace. They are not yet fed into the simulation's virtual-world planner, TTC calculations, or telemetry as if they were calibrated real-world measurements. A later perception-adapter stage must define camera calibration, metric depth/distance estimation, object tracking, and coordinate transforms before that data can safely drive those simulation algorithms. COCO-SSD confidence is not a distance estimate.

The model and library scripts are loaded from public CDNs on first use. Inference runs in the browser; camera frames are not uploaded to an inference API by this implementation.
